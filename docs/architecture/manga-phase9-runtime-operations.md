# 阶段 9：生产治理与验收

本阶段已实现模型调用账本、供应商请求保护、管理员监测、人工账单确认、冷 Run 审计归档，并完成本地隔离故障验证。**工程能力已落地，真实流量、长稳、集群容量与外部安全评估尚未完成，不能据此宣布生产验收通过。**

## 调用链路

`MangaHarnessFactory` 为每个 Harness 建立独立 `MeteredModelFactory` 包装器，底层模型客户端仍由 Kernel 独占和关闭。普通推理及 Compaction 的每次 `Model.stream` 都经过同一边界：

1. 在受控 Manga 阻塞线程池中受理，校验 Run、Step、owner epoch、状态会话和截止时间。
2. 按 Run → 模型配置门禁顺序加数据库行锁。
3. 检查跨实例并发、固定分钟窗口、每日规划预留和熔断。
4. 在 `manga_model_call_ledger` 保存 STARTED、稳定 callId、Run/Step/Blueprint 引用、费率和到期时间，提交后才允许请求供应商。
5. 显式覆盖 SDK 默认重试为一次尝试，禁止一次账本记录在 SDK 内部多次发出请求。
6. 收集 SDK 累计 usage，按各字段最大值处理重复尾块，不逐块累加。
7. 正常、失败、取消均通过 callId + STARTED CAS 关闭账本；同一调用重复关闭不重复结算。
8. 失联或进程退出留下的 STARTED 超时后变为 UNKNOWN，不重新调用供应商。

模型请求最多执行两分钟，同时受 Run 截止时间约束。关闭包装器不会关闭共享客户端。供应商在连接中断后是否仍执行或收费无法由客户端保证，容量租约只表示平台执行许可。

## 费用和对账

新增 V12 迁移：

- `manga_model_call_ledger`：每次实际调用、已报告 token、冻结费率、规划预留、计算费用、人工账单确认。
- `manga_provider_call_gate`：跨进程共享配置门禁、分钟窗口及熔断状态。
- `manga_creative_run_archive`：不可变、可校验的审计副本。

所有表、字段有注释和四个审计字段。SQL 在 Mapper XML 中完整书写，不使用 SQL 片段。

费用分三层，不能互相替代：

| 字段 | 含义 |
| --- | --- |
| reservedUsd | 每个实际模型请求的规划预留额，默认 0.05 USD，失败或取消不退款 |
| calculatedUsd | 冻结费率 × 已报告 token 的计算值；不是供应商账单 |
| settledUsd | 管理员核对账单后明确确认的 USD，包含认证操作者、时间和依据 |

缺失 usage 或模型未定价时，计算费用保持空，界面显示“未知 / 未定价”。失败和取消时即使存在 token，也可能仅是部分用量。额外 cache creation / tool prompt token 没有本平台定价契约时，费用保持未定，不漏算为零。

计算公式为 `(input - cached) × inputPrice + cached × cachedInputPrice + output × outputPrice`，再除以一百万。缓存命中是输入子集，reasoning 是输出子集，二者不重复相加。

`operations.prices` 使用精确模型名。带点号的键要写为 `"[gpt-5.4]"`，保证 Spring 按完整字符串绑定。默认 GPT-5.4 单价参考 [OpenAI 官方文档](https://developers.openai.com/api/docs/models/gpt-5.4)，代理供应商、非标准服务层、长上下文或附加工具费用需覆盖配置并人工核对；不能保证该参考等于你的实际合同价。单次调用在受理时冻结费率。

管理员 `POST /api/v1/admin/creative-operations/calls/{callId}/settlement` 接收 `{amountUsd, note}`。同金额同依据重复确认幂等，冲突或调用未关闭返回 409；已经确认的记录不可覆盖。此功能是账单核对，不会向用户账户扣款。

图片与视频生成仍沿用费用审批与 UNKNOWN 人工对账机制；当前供应商未返回可靠实际 usage/账单，不能把图片预估价记为真实账单，媒体费用不混入文本 token 费用。

## 供应商保护与降级边界

默认按 **模型配置 ID** 共享保护，而非按 Run、Agent 或进程。多个配置即使指向同一供应商账户，也分别计数；真实账户级硬配额还应由供应商或统一网关限制。

| 配置 | 默认 |
| --- | --- |
| 每配置并发 | 4 |
| 每配置分钟受理次数 | 60 |
| 每配置 UTC 每日规划预留 | 10 USD |
| 单请求规划预留 | 0.05 USD |
| 连续可重试故障阈值 | 3 |
| 熔断冷却 | 30 秒 |
| 单模型请求最长时间 | 2 分钟 |

分钟限流采用固定窗口，边界可能短时双倍突发；这不是均匀每秒限流器。每日规划额限制最多受理次数，**不是供应商实际消费硬上限**。失败不退款，防止反复故障绕过配额。

429、5xx、网络异常及超时计入连续故障；冷却后仅放行一个探测调用，成功闭合。门禁状态持久化，进程重启不清空。数据库不可用时封闭失败，不发出模型请求。Redis 状态会话闸门仍先于 Kernel 与 Harness 资源获取。

当前降级方式是：用户选择自己的其他模型配置，使用原有创建 Run API 发起 **新 Run**，重新编译和冻结 Blueprint。原 Run、Step、审批与收费意图不复制为自动重试。Profile 的模型策略和项目权限继续校验；USER_DEFAULT 策略需修改用户默认配置后新建 Run。**本阶段没有实现自动跨供应商降级路由**，执行中的冻结快照不会被替换。

## 指标、告警和面板

管理员侧栏增加“运行监测”，展示近 24 小时调用状态、token、可计算费用、未知费用数量、Run 状态分布和最近 100 个配置门禁；可按 runId 分页追踪调用、Step、owner epoch、失败类型和费用。

接口：

- `GET /api/v1/admin/creative-operations`：管理员摘要。
- `GET /api/v1/admin/creative-operations/runs/{runId}/usage?beforeId=...`：管理员账本。
- `GET /api/v1/creative-runs/{runId}/usage?beforeId=...`：本人 Run 的账本，先校验所有权。
- `POST /api/v1/admin/creative-operations/runs/{runId}/archive`：幂等生成审计归档。
- `GET /api/v1/admin/creative-operations/runs/{runId}/archive`：校验后读取归档，包含用户内容。

Actuator 公开 health/info 安全摘要，`/actuator/metrics` 仅管理员可访问。指标使用有限状态标签，不将用户、runId、任意模型名加入标签：

- `manga.model.calls`、`manga.model.duration`
- `manga.model.rejected`
- `manga.provider.open.circuits`（最近 100 个门禁的有界摘要）
- `manga.operations.failures`

熔断变化、失联调用和归档任务失败记录结构化安全日志；不记录 Prompt、API Key、连接或响应正文。目前是应用指标和日志告警信号，尚未对接外部告警通知平台。恢复后指标从零开始，历史账本不受影响。

## 保留、归档与恢复

AgentState 沿用已实现的 StateSession 保留和清理，晚到写入围栏不变；媒体沿用未采纳对象的独立清理流程，已采纳或有业务引用的产物不被清理。

Run 终态超过 30 天后尝试归档；必须无活动/UNKNOWN 媒体作业、消息投影覆盖终态。审计包包含 Run、冻结预算、Step/Blueprint、有序原始事件、消息及工具状态、委派计划、ChangeSet 与审批。每类最多 10000 行，整个包最多约 16 Mi 字符；读取 LONGTEXT 前先在数据库估算正文量，超过约 4 Mi 字符便保守拒绝，为转义与元数据留余量。超限不截断尾部数据冒充完整归档。

归档保存原始 JSON 字符串和 SHA-256，导出前再次校验并解码核对 runId。它是审计副本，不包含完整业务数据库、媒体二进制或供应商凭据。用量账本单独长期保留，人工对账可以晚于 Run 归档。

在线 Conversation、事件、消息及有引用 Artifact 当前长期保留；**没有自动物理删除策略**。这样仍能重放 SSE、恢复连续对话和追溯审批。需要缩减在线表时，应另行实现冷存储读取路由、SSE cursor 过期契约和隐私删除流程。归档副本与数据库在同一个实例，必须另做异地数据库与对象存储备份。

`tools/verify-creative-audit-archive.ps1 -Path archive-response.json` 可离线校验并解码归档，不覆盖生产数据库。数据库级恢复通过独立备份与独立目标库演练。

## 本次验证与容量边界

没有运行 Maven，没有新增仓库测试用例，没有付费模型调用，也未修改现有数据库。主代码和已有测试均使用本机 JDK 编译，19 个已有相关用例通过，前端生产构建通过；管理面板尚未进行浏览器交互验收。

隔离验证覆盖：

- H2 MySQL 模式完成 40 次断言；独立 MySQL 8.0.31 完成 37 次断言（当时尚未加入 Redis 连接拒绝和晚到 usage 的三项检查）。
- 真实迁移 V1–V12、全部新增字段注释、累计 usage 去重、缓存/推理不重复计价、未知费用、幂等关闭与账单确认。
- 并发、分钟速率、每日规划配额、三次故障熔断、冷却探测、请求截止、取消释放容量。
- 匿名 401、普通用户运维与 metrics 403、管理员 200、Run 跨用户拒绝。
- HMAC 伪造、旧时间戳、正文篡改、超长正文及合法回调重放幂等。
- Redis 连接真实拒绝时，在获取 Kernel 前终止；不连接或关闭现有 Redis。
- 独立 MySQL 完整备份恢复至另一个隔离库：Run、账本行数、已确认金额及归档摘要相同，恢复后的 payload SHA-256 有效。
- 真实 MySQL 停服后的调用前数据库故障，约 741ms 内封闭失败，验证不发出供应商请求。
- 供应商正常、失败、取消采用模型替身；未执行供应商侧真实渗透或压力测试。

单实例本地 **受理竞争检查**：12 个线程提交 60 个并发请求，配置并发上限 2，只放行 2 个；H2 约 110ms、隔离 MySQL 约 181ms。这些耗时不是模型吞吐量、HTTP API 吞吐量或生产容量基线。

默认单配置平台并发上限为 4、固定分钟窗 60 次、每日 200 次规划请求（10 / 0.05）。多实例共享同一配置门禁，因此扩实例不会把这些限额翻倍；全局 Kernel、专用执行线程、数据库连接池和供应商配额还会进一步限制实际并发。不同配置需分别观察，不能直接把所有限额相乘作为集群承诺。

`tools/runtime-operations-probe.ps1 -BaseUrl http://localhost:8080 -Requests 200 -Concurrency 8` 仅测试管理员只读监测接口，令牌从 `MANGA_OPERATIONS_TOKEN` 读取，不会调用模型。输出 p50/p95、吞吐和状态分布；不代表模型执行容量。
